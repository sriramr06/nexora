# Target Audience Identification

**Project:** Nexora — Multi-Tenant Project Management SaaS  
**Phase:** 1 — Product Discovery  
**Step:** 1.1 — Target Audience Identification  
**Version:** 1.0  
**Status:** Completed

## 1. Objective

Identify the intended users of the proposed project management and collaboration platform.

The objective is to establish a realistic user group whose workflows and requirements can guide product discovery and technical design.

## 2. Primary Target Audience

**Software Development Teams**

The platform is intended for teams involved in software development activities, including planning, task management, implementation, testing and project coordination.

These teams may consist of:

- Software developers
- Software testers and QA engineers
- Team leads
- Project managers

**Relationship to tenants:** In Nexora, each organization is a tenant with its own isolated workspace. Software development teams are the primary users working within those organizations.

## 3. User Roles and Responsibilities

| User Type | Typical Responsibilities |
|---|---|
| Developers | Work on assigned development tasks and update progress |
| Testers / QA Engineers | Manage testing tasks, report issues and track their status |
| Team Leads | Coordinate team activities and monitor task progress |
| Project Managers | Organize projects, assign responsibilities and monitor execution |

These are initial user categories. Actual application roles and permissions will be defined during requirements engineering and system design.

## 4. Usage Context

The intended platform will provide a shared workspace where software development teams can:

- Organize projects.
- Create and assign tasks.
- Track task status and priorities.
- Monitor project progress.
- Communicate through task-related collaboration features.

## 5. Project Relevance

Software development teams provide a suitable context for exploring:

- Multi-tenant SaaS architecture.
- Organization and team management.
- Role-based access control.
- Project and task relationships.
- Collaborative workflows.
- Secure resource authorization.

## 6. Scope and Limitations

- The primary audience is limited to software development teams.
- Team size and company size have not yet been formally defined.
- No direct user interviews have been conducted.
- The audience selection is a project-design assumption, not a validated market finding.

## 7. Conclusion

Software development teams have been selected as the primary target audience.

This audience provides a realistic context for designing a project management system while supporting the project's portfolio and backend engineering objectives.
